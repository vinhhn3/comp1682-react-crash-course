Context

Skipping the middle

Context is not “global state”. It is one specific thing: a value that many unrelated components need, delivered without passing it through components that do not care.

1 First, feel the drilling

The cart lives in App. The badge needs it. Two components in between do not.

App const [cart, setCart] = useState([])
AppLayout must accept cart, even though it never reads it
Header must accept cart, even though it never reads it
CartBadge the only one that needs the number

The signature that gives it away

function AppLayout({ children, cart }) {
  return <Header cart={cart} />
}

function Header({ cart }) {
  return <CartBadge count={cart.length} />
}

Two components now have a prop they never use. Move the badge one level deeper and you edit two more files. That is the smell.

It is not always wrong. Two or three levels with an obvious parent-child relationship? Pass the prop. Drilling is only a problem when the middle is unrelated.

2 Now skip it

The provider publishes. The consumer subscribes. The middle never hears about it.

CartProvider value = {{ items, count, add, remove }}
AppLayout nothing changes
Header nothing changes
CartBadge const { count } = useCart()

provider ─ ─ ─ ─ ─ ─ ─ ─ ─ ─► consumer

It is still one-way data flow

The value still comes from above. You did not make global variables — you made the lookup skip the middle. 

// the middle, unchanged
function Header() {
  return <CartBadge />
}

// the consumer asks for it by name
function CartBadge() {
  const { count } = useCart();
  return <span>{count}</span>
}

3 What re-renders when the cart changes

Press “add to cart” in each mode. This is the part everyone guesses wrong.

0 re-rendered
App
AppLayout
Header
CartBadge useCart()
ProductsPage
CartSummary useCart()

With context, the update reaches the two consumers. App, AppLayout, Header and ProductsPage do not re-render just because the cart changed.

4 Use it when…

good fit
  • the signed-in user
  • the cart / basket
  • theme, locale, currency
  • a toast or modal manager

One value, many distant readers, read far more often than written.

not a fit
  • one page's form state
  • a value only a child needs
  • server data — that is a hook's job
  • “everything, in one big provider”

Context has no selector: every consumer re-renders on every change.
