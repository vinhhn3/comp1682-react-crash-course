API handling

One request, six states

A network call is not a function call. It can be slow, it can fail, it can arrive out of order, and it will happen again. Every one of those is a state you have to draw.

1 Who knows what

The rule that makes the rest of this page inevitable: only hooks touch services.

ProductsPage may not know: urls, status codes, retries
useProducts() may not know: JSX, what a URL looks like
productService may not know: React, spinners, which page called it
http() may not know: products. It knows methods, headers, status.
the server knows nothing about you

Why this order matters

If the component calls fetch, then:

  • the URL is in the UI layer
  • every screen re-implements loading and error
  • a 401 means editing every component
  • you cannot test it without a browser
Tell: if you can grep a URL inside src/components, the layer is already broken.

    4 The service translates, the app never learns server words

    This is the “represent” step. One file owns the shape change.

    what the server sends (DTO) 
    {
  id: "p1",
  title: "Aero Mug",
  price_cents: 2400,
  created_at: "2025-03-04T10:12:00Z",
  stock_qty: 12
}
    what the app uses (model) 
    {
  id: "p1",
  title: "Aero Mug",
  price: 24,
  createdAt: Date,
  stock: 12
}
    src/types/product.jsexport function mapProduct(dto) {
  return {
    id: dto.id,
    title: dto.title,
    price: dto.price_cents / 100,
    createdAt: new Date(dto.created_at),
    stock: dto.stock_qty,
  };
}

    Why bother? When the backend renames price_cents, you edit one function. When you swap the API for a different one, you edit one function. And every component stays ignorant of the server's vocabulary.

    6 Three files, three jobs

    services/http.js

    “How to speak HTTP”

    Base URL, headers, JSON, status → HttpError, logging, the mock switch. Nothing about products.

    services/productService.js

    “What the product endpoints are”

    Three methods, three paths. Maps DTOs to models on the way out.

    hooks/useProducts.js

    “What the screen needs”

    { data, loading, error, reload }. Owns the effect, the deps, the abort.
