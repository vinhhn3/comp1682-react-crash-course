One render, one snapshot

Almost every hooks bug comes from one wrong mental model: that count is a variable that changes. It is not. It is a constant inside one call of the component function. Click the buttons below and watch it.

1 State is a snapshot, not a variable

Each click runs the component again, top to bottom, with new constants. The old ones are gone.

src/components/Counter.jsxfunction Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      {count}
    </button>
  );
}

      3 Cleanup is what makes the race disappear
      
    
      Every keystroke starts a request. The cleanup cancels the one before it.
      

    
      
      
      
        
      keystroke “m” render 1 → effect → GET /products?q=m
      
        
      
        
      keystroke “mu” cleanup runs first → abort the “m” request → then the new effect
      
        
      
        
      the “m” response arrives but its signal is aborted — it can never call setState
      
      
      
      
      src/hooks/useProducts.jsuseEffect(() => {
  const controller = new AbortController();

  const fetchProducts = async () => {
    try {
      const data = await getProducts(query, controller.signal);
      setProducts(data);
    } catch (err) {
      if (err.name !== 'AbortError') setError(err.message);
    } finally {
      setLoading(false);
    }
  };

  fetchProducts();

  return () => controller.abort();   // ← this is the cleanup
}, [query]);
      
    
      
  
      

  
  
      
    
      4 Hooks are positional
      
    
      React does not look at names. It keeps a list, and it counts. Skip a hook and everything after it shifts by one.

const [age, setAge] = useState(0)

render 1 (user = null): slots → [age]
render 2 (user = ana):  slots → [name, age]
                           ^ age now reads the name slot

      5 The four bugs you will actually write
      
    
      

      
      
        infinite loop
        
      useEffect(() => {
  setData(compute())      // sets state…
})                        // …on every render
      
        
      No array = runs after every render = new render = forever.
      
      
      

      
      
        stale closure
        
      useEffect(() => {
  const id = setInterval(() => {
    setCount(count + 1)   // frozen at 0
  }, 1000)
}, [])
      
        
      The effect captured the first render's count. Use c => c + 1.
      
      
      

      
      
        async callback
        
      useEffect(async () => {
  const data = await fetch(...)
}, [])
      
        
      It must return the cleanup, not a Promise. Call an inner async function instead.
      
      
      

      
      
        no cleanup
        
      useEffect(() => {
  fetch(url).then(setData)
}, [url])
      
        
      Type fast: two requests, no ordering. The last one to arrive wins — and it may be the wrong one.
